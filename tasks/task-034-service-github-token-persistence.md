# [Done] TASK-034: Сервисный GitHub token (сохранение между входами)

## Контекст

До изменения пользователь должен был вставлять GitHub token почти при каждой работе с деплоем (`автозаполнение` и `создание PR`). Это приводило к лишним шагам, ошибкам и ухудшало UX. Нужен был механизм, где токен можно один раз сохранить на уровне сервиса и дальше использовать по умолчанию.

## Что требовалось

- Хранить GitHub token между входами пользователя.
- Добавить управление токеном на уровне сервиса: добавить/обновить/удалить.
- Использовать сохраненный токен в GitHub-операциях проекта, если в форме не передан разовый токен.
- Не хранить токен в открытом виде.

## Что сделано (кратко)

- Добавлено шифрованное хранение токена в `users` (`github_token_encrypted`) + миграция БД.
- Реализованы API-эндпоинты:
  - `GET /service/github-token`
  - `PUT /service/github-token`
  - `DELETE /service/github-token`
- В сервисном слое добавлены операции чтения/сохранения/удаления токена и fallback-логика:
  - если `githubToken` не передан в `github/questions` и `github/bootstrap`, используется сохраненный сервисный токен.
- В UI добавлена кнопка `Токен` в верхнем баре и модалка управления токеном (сохранить/удалить, индикация статуса).
- Для deploy-формы сохранен режим разового override токена; при вводе токена он также сохраняется как сервисный.
- Добавлены/обновлены unit/API тесты для lifecycle токена.

## Готово, если

- [x] Токен сохраняется между входами пользователя.
- [x] Есть сервисная точка управления токеном (добавить/обновить/удалить).
- [x] GitHub-операции работают без ручного ввода токена, если он уже сохранен.
- [x] Токен хранится в зашифрованном виде.
