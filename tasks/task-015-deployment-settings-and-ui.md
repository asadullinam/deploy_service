# [Done] TASK-015: Настройки деплоя как часть проекта и улучшение UX консоли

## Контекст

Пользователь заполняет одни и те же поля снова и снова:

- owner/repo
- branch
- service name
- dockerfile path
- service type
- service/container ports

Часть этой проблемы уже решена: настройки можно хранить в самом проекте. Но это нужно оформить как полноценную функцию платформы, а не как побочный эффект bootstrap.

## Что сделать

### 1. Описать deployment settings как first-class часть Project

Зафиксировать в модели проекта набор полей, которые живут между сессиями:

- `repositoryOwner`
- `repositoryName`
- `baseBranch`
- `serviceName`
- `dockerfilePath`
- `serviceType`
- `servicePort`
- `containerPort`

GitHub token не хранить.

### 2. Выделить отдельный endpoint для редактирования

Сейчас UI может сохранять настройки автоматически. Нужно явно поддержать это как API capability:

```
PUT /projects/{id}/deployment-settings
GET /projects/{id}
```

`GET /projects/{id}` должен возвращать уже готовые настройки для автозаполнения формы.

### 3. Сделать UX автосохранения явным

Сейчас пользователю полезно видеть:

- “сохранено”
- “сохраняем…”
- “не удалось сохранить”

Нужен лёгкий visual feedback, чтобы пользователь понимал, что форма уже привязана к проекту.

### 4. Доделать безопасный UX для GitHub token

Нужно:

- masked field по умолчанию
- кнопка show/hide
- не сохранять token в БД
- не сохранять token в browser storage
- очистка token после успешного PR по желанию пользователя или автоматически

### 5. Добавить тесты на персистентность настроек

Сценарии:

1. пользователь сохраняет deployment settings
2. перезагружает страницу
3. выбирает проект
4. видит те же значения из БД

## Готово, если

- Пользователь не вводит заново базовые настройки деплоя для одного и того же проекта
- Чувствительные токены не сохраняются
- UI ясно показывает, что именно сохранено, а что нет

## Статус проверки

**Выполнена в основном.**

**Реализовано:**

- Все 8 полей `UpdateDeploymentSettingsRequest`: `service_name`, `dockerfile_path`, `container_port`, `service_port`, `service_type`, `base_branch`, `repository_owner`, `repository_name`
- `PUT /projects/{id}/deployment-settings` сохраняет настройки, `GET /projects/{id}` их возвращает
- UI с дебаунсным автосохранением (500ms)
- GitHub-токен — masked (`type=password`) со show/hide, хранится в `sessionStorage`, не сохраняется в БД
- Toast-уведомления при ошибке сохранения

**Не реализовано:**

- Нет visual feedback об **успешном** сохранении (toast "настройки сохранены") — только ошибки
- Нет автоматических тестов персистентности настроек через API
