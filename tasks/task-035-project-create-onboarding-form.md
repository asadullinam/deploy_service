# [Done] TASK-035: Форма первичной настройки проекта при создании

## Контекст

Сейчас после создания проекта пользователю приходится вручную и повторно вводить базовые данные для деплоя. Это замедляет старт, повышает риск ошибок и делает первый запуск менее понятным.

Нужен единый шаг первичной настройки сразу после создания проекта: пользователь один раз вводит постоянные параметры, а дальше система использует их по умолчанию. Эти параметры должны оставаться редактируемыми в любой момент.

## Проблема

- Нет обязательного шага первичной конфигурации проекта.
- Пользователь не получает сразу явную инструкцию про `KUBECONFIG_BASE64` в GitHub Secrets.
- Базовые параметры проекта не собираются как "постоянные" в одном месте при создании.

## Что сделать

### 1. Добавить форму первичной настройки после создания проекта

После успешного создания проекта показать форму (экран/модалка) с постоянными данными:

- Ссылка на репозиторий GitHub
- Основная ветка
- GitHub token

### 2. Добавить предупреждение про GitHub Secret `KUBECONFIG_BASE64`

В этой же форме показать заметный warning:

- Нужно добавить в GitHub Secrets ключ `KUBECONFIG_BASE64`.
- Дать готовые команды получения base64 из kubeconfig:

Linux:

```bash
base64 -w 0 ~/.kube/deploy-service.yaml
```

macOS:

```bash
base64 < ~/.kube/deploy-service.yaml | tr -d '\n'
```

### 3. Сохранение и повторное использование

- Введенные данные сохраняются как постоянные настройки проекта.
- При следующих действиях они не должны переспрашиваться автоматически.
- Пользователь может в любой момент изменить их на странице настроек/деплоя проекта.

### 4. UX и валидация

- Проверка формата ссылки на репозиторий.
- Проверка, что ветка не пустая.
- Токен вводится в password-поле с возможностью показать/скрыть.
- Понятные тексты ошибок и подсказок.

- В модалке реализованы поля `GitHub URL`, `основная ветка`, `GitHub token` (с кнопкой показать/скрыть).
